# 13. 本番運用に向けた未実装の一覧（ログイン・アカウントまわりを中心に）

店舗CMS と利用者アプリ「まちクエ」を実際の店舗・利用者で動かすときに要る機能のうち、まだ無いものをまとめる。
2026-11-10 作成。docs/09（CMS 要件）・docs/11（運用）・docs/12（利用者データのサーバー）・docs/audit/20261109_security.md と、同日時点のコード（API の道筋・画面）を照らし合わせた。

- 個々の要件の中身は元の文書にある。ここは「何が残っているか」と「どれから要るか」だけを書く。
- 実装が進んだら、該当の行を消すか「済」にする。

**優先度の見方**

| 記号 | 意味 |
|---|---|
| **必須** | これが無いと公開できない（安全・法令・運用が成り立たない） |
| **高** | 公開の直後から困る。公開までに入れたい |
| **中** | 運用が回り始めてからでよい |
| 判断 | 作る前にユーザー（企画側）の決定が要る |

## 0. いまできていること（前提）

| 範囲 | できていること |
|---|---|
| CMS のログイン | ID＋パスワード（scrypt）、セッション Cookie（12時間／無操作60分）、5回失敗で15分ロック、ログイン 10回/分、ログアウト、自分のパスワード変更 |
| CMS の権限 | 運営者／店舗の2ロール。店舗は担当店舗だけ（サーバー側で照合）。運営者によるアカウントの作成・担当店舗・停止と再開・パスワードの作り直し。CLI での最初の運営者の作成 |
| CMS の配置 | アプリと別オリジン（`--cms-port`）、TLS か中継が無いと起動しない、許可するホスト名、認証の記録（`cms_auth_log`） |
| アプリのログイン | 外部ログイン（OIDC 認可コード＋PKCE）の仕組み、セッション Cookie（30日／無操作14日・仮）、ログアウトの API、未ログイン時のログイン画面。**実物の LINE・Google では未確認**（開発用のにせの提供元だけで確認） |
| アプリのデータ | 発見・訪問・購入・チケットをサーバーで実行（PostgreSQL。この PC では PGlite）。移動の速さの確認 |
| 運用 | ビルド手順、Dockerfile、nginx・systemd の例、SQLite のバックアップ手順（docs/11） |

| # | 未実装 | 優先度 | 元の要件 | 補足 |

| C-8 | ログイン中の端末の一覧と、個別に切る操作 | 中 | — | 今は「パスワード変更でほかの端末を切る」「停止で全部切る」だけ |

## 6. 進める順の案

1. **ユーザーの決定を先にもらう**：A-1（LINE／Google の登録・ドメイン）、I-1（ホスティング）、A-6（規約・ポリシーの文面）、C-5（申請制か招待制か）、S-1（掲載確認の体制）。外部の審査や法務の確認は待ち時間が長い。
2. **決定を待たずに作れるもの**：C-1（2要素認証）、A-2・A-3（ログアウト・セッション切れ）、A-4・A-5（退会・書き出し）、D-1〜D-4（領主・ランキング・クーポンの反映・装い）、C-9、C-11、S-2、I-5（CI）。
3. **接続先が決まったら**：I-2・I-3（本物の PostgreSQL）、A-1 の通し確認、I-4（SQLite の統合）、I-6〜I-8。
4. **メールの手段が決まったら**：C-6 → C-3 → C-2。
