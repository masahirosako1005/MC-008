## 1. 対象と方法

本番のホスティングは未決（docs/11 §7）のため、**本番の版をこの PC で本番と同じ設定で起動したもの**を標的にした。インターネット上の実環境への攻撃はしていない。

| 標的 | 中身 |
|---|---|
| `https://127.0.0.1:18787`（公開の面） | 本番の版。利用者アプリ＋公開 API＋利用者データの API（`/api/app/*`。PGlite、Google のにせの設定） |
| `https://127.0.0.1:18788`（CMS の面） | 本番の版。店舗CMS＋`/api/cms/*`＋`/api/auth/*`。TLS、`--allowed-hosts app.example.jp,admin.example.jp` |
| `http://127.0.0.1:18797` | デモの版＋開発用ログイン。ログイン後の処理（本番と同じコード）を試すためだけに使用 |

- ビルドと DB は `.data/sec/`（git に入らない）に隔離。ほかのセッションの `dist*`・5173・5199 には触れていない
- 演習用アカウント（運営者 1・店舗 2）は演習用 DB にだけ作成
- 攻撃役の決まり：標的のポート以外・インターネットへは送らない、プロジェクトのファイルは読むだけ、長時間の大量送信はしない

## 3. 指摘と対応

### Medium（すべて修正済み）

| ID | 指摘 | 攻撃での証明 | 対応 |
|---|---|---|---|
| RA-01 | 購入・チケットの利用に移動速度の確認（DI-14）が効かない。訪問をしない利用者は、全店舗の購入 EXP を一気に取れる | 2.3km 離れた 2店で 90 ミリ秒のうちに購入が両方成功 | 起点を「訪問・購入・チケットのうち最新」に変更（`visitPlausibility.ts`、`appPlayRoutes.ts`）。テスト追加 |
| R2-01 | 上の修正後も、250m ずつの移動をつなぐと 0.5 秒で 2km 進める（直前の1件としか照らさない・端末が申告する精度をそのまま誤差に足す） | 19店を 496 ミリ秒で連続購入（EXP 10→200） | 直近 60 分の行動すべてと照らす。申告の精度は 30m までしか見込まない。マスタに無いスポットの行動は飛ばして次を見る。再攻撃で 19 中 16 を拒否 |
| RO-02 | 公式のビルド手順が、利用者アプリを「端末が正」の版で作る（サーバー側の守りが使われない） | ビルド手順とできた物の確認 | `scripts/build/backend.mjs` に `--app-backend server`、`Dockerfile` に `APP_BACKEND`。付けないとビルド時に注意を出す。docs/11 §2 |
| RO-06 | 手順の例（`--host 0.0.0.0 --trust-proxy`、`docker run -p 8787:8787`）だと、平文のポートが外から届き、`X-Forwarded-For` を偽って回数制限を逃れられる | 設定の確認（標的は該当設定でないため攻撃は未実施） | 例を `127.0.0.1` の待ち受け・`-p 127.0.0.1:…` に変更、注意書きを追加（docs/11 §3、`Dockerfile`） |

## 4. 攻撃して破れなかったもの（主なもの）

- 店舗のアカウントから他店の参照・更新、運営者の機能 → すべて 403（道筋の書き方の工夫も不可）
- ログイン：総当たり・ロックの回り道・ID の有無の推測・セッションの固定 → 不可。トークンは DB にハッシュだけ
- 本番の版でのデモのログイン・やり直し・にせの提供元 → 404。本番の画面ファイルにデモ機能・秘密・ソースマップ無し
- SQL 注入・prototype pollution・壊れた本文 → 400 系で拒否、500 なし。CMS の入力はアプリで文字として表示（XSS 不可）
- ほかの利用者のデータ：利用者 ID はセッションからだけ取るので指定できない。本文の `points`・`travelerId` は無視
- 同じ購入の同時 25 連打 → EXP が付くのは 1回だけ
- 外部ログイン：偽の `code`／`state` の戻り・ログインの CSRF・戻り先のすり替え → 不可
- 静的ファイルの外の読み出し（DB・TLS の鍵）→ 404
- 壊れた要求・途中で切る接続 126 通り → サーバーは落ちない
- `npm audit` 0 件。ログにパスワード・トークン・座標なし
