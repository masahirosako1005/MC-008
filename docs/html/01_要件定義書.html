まちクエ 要件定義書

N西市 再訪促進スマホWebアプリ「まちクエ」と、店舗向け CMS の「何を作るか」をまとめたもの。元の文書（CLAUDE.md・docs/09・docs/13）を1枚に整理しています。

目次

このアプリは何か

元の文書CLAUDE.md 冒頭・§1
観光地を「一度で消費する場所」から「何度も訪れて育てる場所」へ変える。

アプリ名

まちクエ（街がクエストの場所）
一言：この街が、クエストになる。

コンセプト

街に通うほど、自分だけの街が育つ。

形

スマホ縦型の Web アプリ（基準幅 390px）＋店舗向け CMS

背景と課題

利用者

名所を回り終えると「コンプリートした」と感じ、再訪する理由がなくなる。

地域

新規客の獲得は高くつく。リピーターが店舗と周辺を回遊することが、収益と賑わいに直結する。

既存アプリ

スタンプラリー型（網羅＝ゴール）が多く、達成した瞬間に離脱する。

狙い「網羅」をゴールにせず、「通い続けること」自体を楽しく・価値あるものにする。

既存サービスとの違い

既存弱点まちクエ
スタンプラリー型埋めたら終わる「完成しない街」で終わりを作らない
位置情報ゲーム現地の観光と無関係に遊べる実在スポットの訪問と便利情報が軸
観光情報サイト初回の情報提供で止まる色あせと復活で「また行く理由」を作り続ける

だれのためか（ターゲットと提供価値）

元の文書CLAUDE.md §2・§3
主ターゲット観光地から車・電車で1時間圏内に住み、週末に気軽に出かける近隣観光客。

子連れファミリー

トイレ・休憩・ベビーカー情報を重視。1回は短く、回数で楽しむ。

カップル・友人同士

期間限定イベント・新店に反応しやすい。

一人歩き・散歩好き

未開拓スポットの発見、通った回数の積み上げに反応しやすい。

副次ターゲット：観光地側（店舗・自治体・DMO）。店舗協力なしでも成立し、協力すると来店導線とクーポン配信が得られる。

提供価値

利用者

  • 初回：迷わない・困らない（便利情報、近隣スポットと距離、次に行く理由）
  • 2回目以降：まだ知らない場所が見える、自分の街が育つ、戻ると「おかえり」と迎えられる

地域

  • 来訪頻度と回遊範囲の増加。名所だけでなく店舗への送客
  • 期間限定イベント・クーポンの告知先を持てる
  • 地区別・曜日別の来訪傾向が見える（将来）

累計 EXP が決まった数に届くとアバターの部品。ランクアップ（50・150・400・800）は称号、その間と先（25・100・220・300・500・650・1000・1200）は髪の色・服の色・称号。

全画面に共通の要件

文字は最小限

説明文・ヒント・手順を足さない。言葉より絵と動きで見せる。

絵はすべて自作

アイコン・絵は Canvas で描く。絵文字・アイコンフォント・既製画像は使わない。

色だけに頼らない

色あせは透明度と小さなアイコンでも示す（色覚配慮）。

写真

名所は実写、店舗はカテゴリの「イメージ」写真。Wikimedia Commons の利用可能なものだけ、出典を表示。

店舗 CMS の要件

元の文書docs/09_store_cms_requirements.mdコードの場所cms.htmlsrc/presentation/cms/

店舗と運営者（自治体・DMO）が、店舗情報・クーポン・イベント・店頭 QR を登録し、来訪の集計を見るための管理画面。

付加機能である

店舗が参加しなくても、CMS が止まっていても、アプリは成立する。

失う体験を作らない

クーポンの取り下げ・協力店の解除・閉店をしても、利用者の Lv・カード・図鑑・EXP は減らさない。

集計値だけを渡す

店舗には個人を特定できる形で出さない。5人未満は「少数」と表示。

セキュリティ

  • サーバーが正：端末が送るのは「訪問したい」という意図だけ。距離・1日1回・EXP はサーバーが計算
  • すべての API でロールと担当店舗をサーバー側で確認
  • CMS はアプリと別オリジン。Cookie は HttpOnly・Secure・SameSite
  • 入力はテキストとしてだけ表示（innerHTML・eval 禁止）
  • 回数制限（ログイン・書き込み）、秘密情報をリポジトリに入れない

データ完全性

  • 外部データは境界で検証してから使う
  • 訪問・発見・台帳は追記だけ。残高や Lv は記録から導出し、保存しない
  • 操作 ID で二重登録を防ぐ、版数で同時編集を検出
  • 失敗は Result で返す

プライバシー

  • 座標を残さない：保存するのはスポット ID・地区・日時だけ
  • 集めない：外部ログインから受け取るのは提供元と利用者 ID だけ（メール・氏名・写真は要求しない）
  • 店舗には集計値だけ。写真の EXIF（撮影位置）を消す

使いやすさ・可用性

  • スマホ片手、主要操作はタップ2回以内、タップ領域 44px 以上、文字拡大3段階
  • CMS は幅 360px から、IT に不慣れな店員でも使える
  • CMS や API が止まっても、アプリは前回の写しで動く
